# 임진왜란 캠페인 설계

- 작성일: 2026-10-02
- 기준 코드: yairm210/Unciv `master` 69de0af5c (4.22.6-patch1), 작업 브랜치 `imjin-campaign`
- 상태: 설계 확정, 구현 계획 작성 전

## 1. 목표

Unciv 위에 임진왜란(1592~1598)을 다루는 고정 스토리 캠페인을 만든다. 플레이어는 조선을 맡아 육지와 바다 양쪽에서 싸운다. 큰 역사 흐름은 고정하고, 장 사이 이벤트에서 고른 선택이 이후 장의 전력과 에필로그를 바꾼다.

### 확정된 결정

| 항목 | 결정 |
|---|---|
| 형태 | 고정 캠페인. 장마다 정해진 맵, 문명, 배치 |
| 배경 | 한국사, 임진왜란 |
| 관점 | 조선 전체 (해전 + 육전 + 의병 + 명 원군) |
| 엔진 수정 | 모드(JSON) 중심 + 최소 엔진 패치. 패치는 Unciv 본가에 PR할 수 있는 범용 기능으로 만든다 |
| 분기 | 큰 흐름 고정, 선택은 스토리 플래그로 누적되어 장별 전력과 에필로그(2~3종)에 반영 |
| 구조 | 장별 개별 시나리오 + 장 사이 이벤트 (접근법 A) |
| 아트 | AI 생성. 코덱스 짭 MCP의 GPT 이미지 도구 사용 |

## 2. 단계 구분

| 단계 | 내용 |
|---|---|
| **1단계 (이 문서의 구현 범위)** | 엔진 패치 1·2, 모드 골격, 시나리오 빌드 도구, 프롤로그 + 1장 완성 |
| 2단계 | 엔진 패치 3 구현 + 2장. 장 간 플래그 이월을 실제 콘텐츠로 검증 |
| 3단계 이후 | 3~6장, 에필로그 분기, 명나라 원군 |

패치 3을 2단계로 미루는 이유: 1장만 있으면 넘어갈 다음 장이 없어 이월을 검증할 수 없다. 1단계에서는 프롤로그를 1장 시작 이벤트로 넣어서, 패치 3 없이도 프롤로그 선택이 1장에 반영되게 한다.

## 3. 캠페인 구성

|---|---|---|---|---|
| 프롤로그 | 1590~91 | (1장 시작 이벤트) | 서사 | 통신사의 엇갈린 보고, 이순신의 전쟁 준비 |
| 1장 | 1592.5~6 | 옥포~당항포 | 해전. 첫 승, 거북선 첫 출전 | 부산진·동래성 함락, 원균의 구원 요청 |
| 2장 | 1592.7 | 한산도 | 해전. 학익진 | 선조의 의주 피난, 명에 원병 요청 여부 |

### 스토리 플래그

| 플래그 | 의미 | 영향 |
|---|---|---|
| `수군` (Navy) | 이순신과 함대 관련 선택 | 해전 장의 시작 함선 수와 승급 |
| `민심` (Morale) | 백성과 의병 관련 선택 | 의병 유닛 수, 도시 충성도 |
| `조정` (Court) | 조정 결속과 명과의 관계 | 명 원군의 규모와 도착 시점 |

이순신의 전사 같은 큰 사건은 바뀌지 않는다. 에필로그는 전쟁 뒤 조선의 모습(재건, 개혁, 혼란)만 달라진다.

## 4. 엔진 패치

공통 원칙: 새 필드나 새 동작을 쓰지 않는 기존 모드와 시나리오는 지금과 똑같이 동작해야 한다. Unciv의 JSON 로더는 `ignoreUnknownFields = true`(`json/UncivJson.kt:23`)라서 필드를 추가해도 구버전·구모드와 충돌하지 않는다.

### 패치 1: 시나리오의 플레이어 문명 고정 (1단계)

**문제**: 시나리오를 시작하면 사람 플레이어가 무작위 주요 문명에 배정된다. `NewGameScreen.startNewGame()`(`ui/screens/newgamescreen/NewGameScreen.kt:317-341`)이 모든 문명을 AI로 바꾼 뒤, 플레이어 목록의 "Random" 슬롯마다 무작위 문명을 고른다. 플레이어 목록에 문명이 명시돼 있으면 그대로 따르지만, 시나리오 선택 시 그 목록을 채우는 코드가 없다. `docs/Modders/Scenarios.md:28`도 이 기능이 없음을 명시한다.

**변경**:
- `ui/screens/newgamescreen/ScenarioSelectTable.kt` `selectScenario()`: 시나리오 미리보기의 문명 중 `playerType == Human`이고 관전자가 아닌 문명마다, 플레이어 목록의 Random 슬롯을 `Player(civID, Human)`으로 바꾼다. 슬롯이 모자라면 추가한다.
- `ui/screens/newgamescreen/PlayerPickerTable.kt`:
  - 잠긴 상태(`locked`)에서 명시된 문명 슬롯은 AI/Human 토글을 비활성화한다.
  - `reassignRemovedModReferences()`가 "Will not be chosen for new games" 문명을 Random으로 되돌리는 동작을, 잠긴 상태에서는 건너뛴다.
- `docs/Modders/Scenarios.md`: 시나리오 제작자가 콘솔 `civ setplayertype <civ> human`으로 플레이어 문명을 지정하는 방법을 문서화한다.

**하위 호환**: 사람 플레이어 문명이 저장되지 않은 시나리오(관전자로 저장한 기존 시나리오)는 지금처럼 무작위 배정된다.

### 패치 2: 이벤트의 화자와 초상화 (1단계)

**변경**:
- `models/ruleset/Event.kt`: `Event`에 `speaker: String = ""`(화자 이름, 번역 대상)와 `portrait: String = ""`(이미지 이름)을 추가한다.
- `ui/screens/worldscreen/RenderEvent.kt`: 둘 중 하나라도 비어 있지 않으면 본문 라벨 위에 초상화와 화자 이름 줄을 그린다.
  - 이미지 탐색 규칙은 `FormattedLine`의 `extraImage`와 같다. 아틀라스 이미지를 먼저 찾고, 없으면 `ImageGetter.findExternalImage()`로 모드의 `ExtraImages` 폴더에서 찾는다.
  - 이미지를 못 찾으면 초상화 없이 이름만 그린다.
- `models/translations/TranslationFileWriter.kt`: `portrait` 필드를 번역 제외 목록(`untranslatableFieldSet`)에 넣는다.
- `docs/Modders/schemas/Events.schema.json`: 두 필드를 추가한다. 이 스키마는 `additionalProperties: false`라서 추가하지 않으면 편집기가 경고한다.
- `docs/Modders/Mod-file-structure/5-Miscellaneous-JSON-files.md`의 Events 표에 두 필드를 추가한다.

**대화 표현**: 여러 사람이 주고받는 대화는 이벤트 사슬로 만든다. 한 이벤트가 한 사람의 대사이고, "계속" 선택지가 `Triggers a [다음 이벤트] event`로 다음 대사를 띄운다. 실제 선택지는 마지막 이벤트에만 둔다. 이 연결은 엔진에 이미 있다.

### 패치 3: 다음 장으로 넘어가기 (2단계에서 구현, 설계만 확정)

### 스토리 스크립트: 장 본영 건물

각 장의 대본은 그 장의 본영 건물에 붙은 발동 유니크 목록이다. 시나리오 빌드 도구가 이 건물을 조선 수도에 미리 지어둔다.

전역 설정(GlobalUniques)에 대본을 넣지 않는 이유: 모든 장에서 동시에 발동하고, 조건을 걸지 않으면 AI 문명에게도 걸려 AI가 선택지를 자동으로 고른다.

사용하는 엔진 기능(모두 기존 유니크):

| 용도 | 방법 |
|---|---|
| 시작 이벤트를 한 번만 | `Triggers a [이벤트] event <upon turn start> <when number of [프롤로그 완료] is equal to [0]>`. 마지막 선택지가 플래그를 1로 올린다 |
| 특정 턴의 사건 | `<after turn number [N]>`, `<before turn number [N]>`와 진행 플래그 조합 |
| 해역 진입 대사 | 유닛 유니크 `<upon entering a [tileFilter] tile>` |
| 격침 집계 | 조선 함선 유니크 `Instantly provides [1] [격침 수] <upon defeating a [mapUnitFilter] unit>` |
| 플래그 변경 | `Instantly provides [n] [플래그]`, `Instantly consumes [n] [플래그]` |
| 플래그 판정 | `Only available <when number of [플래그] is more than [n]>` |
| 장 승리 | 승리 이정표 `Have at least [N] [격침 수]` |

### 패배 처리 (구현 계획에서 확정, 엔진 수정 없음)

엔진에는 "특정 조건에서 사람 플레이어 패배" 장치가 없다. 대신 일본 전용 승리 조건 `Japanese Conquest`를 둔다. 이 조건의 이정표는 `Have at least [1] [[Defeat Flag] resource of [Human player] Civilizations]`다. 다른 문명의 자원을 세는 countable(`Countables.kt:398`)이 이미 있어서 엔진 패치가 필요 없다.

조선의 장 본영 건물이 이순신 전사나 제한 턴 초과 때 `Defeat Flag`를 올린다. 그러면 일본의 승리가 성립하고, 플레이어는 그 승리 조건의 `defeatString`을 패배 화면에서 본다.

### 계획 단계에서 확정한 세부

- **이순신 유닛**: 위대한 제독(민간 유닛)이 아니라 원거리 전투 함선(지휘선)이다. 주변 함선 강화 유니크를 갖는다. 민간 유닛은 호위가 죽으면 포획되어 전사 판정이 애매하기 때문이다.
- **프롤로그 첫 표시**: 시나리오를 불러온 첫 턴에는 턴 시작 발동이 돌지 않는다. 그래서 시나리오 빌드 도구가 세이브의 팝업 대기열에 첫 이벤트를 넣는다. 이벤트 팝업에는 닫기 버튼이 없어서 선택지를 골라야만 넘어간다.
- **해역 표시**: 이미지 없는 지형 특성(`Okpo Waters`, `Sacheon Waters`)을 연안 타일에 깐다. 지형 특성 이름은 tileFilter로 바로 쓰이고, 이미지가 없으면 맵에 그려지지 않는다. 타일 정보에는 "옥포 앞바다"처럼 표시된다.
- **연도**: 모드 게임 속도 `Imjin War`로 1592년부터 표시한다(턴당 약 3.65일).
- **승리 조건의 "Will not be chosen for new games"**: 새 게임 화면의 체크박스에서만 빠진다(`Ruleset.kt:205-207`). 시나리오 세이브에 적힌 승리 조건은 그대로 켜진다.

     - 통신사 보고: 황윤길(전쟁 대비)을 믿으면 수군+, 김성일(민심 안정)을 믿으면 민심+
     - 이순신의 전쟁 준비: 거북선 건조를 지원하면 1장 거북선 +1, 조정 −
  2. 개전 브리핑: 부산진·동래성 함락, 원균의 구원 요청
     - 즉시 출전: 바로 시작
     - 전라우수영(이억기) 합류 대기: 판옥선 2척이 늘어나는 대신 제한 턴이 40에서 36으로 줄어든다
  3. 전투 중 사건
     - 옥포 해역 첫 진입: 이순신 대사 "가볍게 움직이지 말라, 산처럼 무겁게"
     - 사천 해역: 거북선 첫 출전, 이순신의 어깨 총상
- **승리**: 이순신 생존 상태로 제한 턴 안에 일본 함선 N척 격침
- **패배**: 이순신 전사 또는 제한 턴 초과
- **승리 후**: 마무리 이벤트, "2장에서 계속됩니다"
- N, 제한 턴, 척수 같은 수치는 플레이 테스트로 정한다.

## 7. 시나리오 빌드 도구

장별 시나리오를 맵 편집기와 콘솔로 손수 만들지 않고 코드로 생성한다.

- **입력**:
  - 맵: 문자로 그린 지형 배치도(문자 하나 = 타일 하나)
  - 배치 설정: 문명, 도시, 유닛, 건물(장 본영 포함), 전쟁 상태, 기술, 시작 플래그, 사람 플레이어 문명(패치 1용)
- **출력**: 시나리오 세이브를 `campaign/Imjin War 1592/scenarios/`에 쓴다.
- **위치**: 개발용 도구다. 본가 PR에는 포함하지 않는다. 코드는 `campaign/tools/src`에 두고 tests 모듈의 소스셋에 추가한다. 실행은 Gradle 태스크 `:tests:buildScenarios`로 한다.
- **맵 원본**: `campaign/maps/ch1-south-sea.txt`는 `campaign/tools/mapgen/south_sea.py`가 남해안 경위도 해안선에서 만든다.
- 밸런스 조정은 설정만 바꾸고 다시 빌드한다. 2~6장에서 재사용한다.

## 8. 아트

모든 이미지는 코덱스 짭 MCP의 GPT 이미지 도구로 생성한다. 본 생성 전에 기준 이미지 1장으로 화풍을 확인받는다.

| 종류 | 대상 (1단계) | 규격 |
|---|---|---|
| 인물 초상화 | 선조, 류성룡, 이순신, 원균, 이억기, 황윤길, 김성일, 도요토미 | 정사각 PNG, `ExtraImages/` |
| 지도자 초상화 | 선조, 도요토미, 만력제 | Unciv `LeaderIcons` 규격 |
| 장면 삽화 | 부산진 함락, 옥포 해전, 거북선 출전 | 가로형 PNG, `ExtraImages/` |
| 유닛 아이콘 | 판옥선, 아타케부네, 세키부네, 이순신 | Unciv 규격(투명 배경 흰 실루엣) |
| 문명 아이콘 | 조선, 일본(도요토미), 명 | Unciv `NationIcons` 규격 |

화풍: 전통 채색화 느낌의 반실사 일러스트로 통일한다. 정확한 픽셀 규격은 구현 계획에서 기존 에셋을 측정해 정한다.

## 9. 언어

- 문명, 유닛, 자원, 건물의 내부 이름은 영어로 둔다. 파일명과 아이콘 경로에 쓰이기 때문이다. 화면 표시명은 모드의 `Korean.properties`로 붙인다.
- 이벤트 본문, 대사, 선택지 문구는 처음부터 한국어로 쓴다.
- 영어판은 범위 밖이다.
